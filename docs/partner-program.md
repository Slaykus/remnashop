# Партнёрская программа

Решения приняты 15.08.2026. Документ ведём по мере работы: он объясняет
не только что делаем, но и почему именно так — чтобы через полгода не
переигрывать заново уже обдуманное.

## Чем отличается от реферальной системы

Реферальная система даёт дни подписки и работает между обычными
пользователями. Партнёрская предполагает **денежные выплаты** людям,
которых владелец набирает отдельно. Отсюда требования, которых у
рефералки нет: неизменяемый журнал начислений, период удержания,
собственный кабинет с историей.

## Принятые решения

| Вопрос | Решение | Почему |
|---|---|---|
| Модель выплат | Процент со **всех** платежей приведённого клиента, включая продления | Мотивирует вести живой трафик, а не разовые регистрации |
| Атрибуция | **Первое** касание | Защищает от перехвата чужого трафика: партнёру бесполезно догонять рекламой уже наших клиентов |
| Кабинет партнёра | На **сайте**, отдельный раздел | Работает для партнёров без Telegram, удобнее для таблиц и выгрузок |
| Порядок работ | Сначала фундамент | Партнёрка ляжет на исправленную основу |
| Ставка по умолчанию | **35%** со всех платежей клиента за всё время | Решено 15.08.2026 |
| Удержание по умолчанию | **7 дней** | Решено 15.08.2026 |
| Минимальная выплата по умолчанию | **500 ₽** | Решено 15.08.2026 |
| Где задаются условия | У каждого партнёра свои, правятся в разделе рекламы | Решено 15.08.2026 |

## Устройство

**Не строим вторую систему.** У рекламных ссылок уже прослеживается вся
воронка: переходы → уникальные пользователи → пробный период → оплаты →
выручка. Партнёрская ссылка — это та же рекламная, у которой появился
владелец.

- `ad_links` получает владельца. Без владельца — своя реклама, как
  сейчас; с владельцем — партнёрская.
- Новая роль `PARTNER` рядом с существующими.
- Журнал начислений: строка на каждый засчитанный платёж — сумма, ставка,
  статус, дата доступности.
- Журнал выплат: что и когда фактически отдано.

### Деньги считаем в момент платежа

Сейчас выручка вычисляется запросом задним числом: «все оплаты этого
человека после клика». Для аналитики годится, для денег — нет.

Во-первых, если человек прошёл по двум партнёрским ссылкам, обе получат
в зачёт один и тот же платёж, и мы заплатим дважды. Во-вторых, цифра
задним числом может измениться, а партнёру уже выплачено.

Поэтому: когда платёж подтверждён, **один раз** определяем партнёра по
правилу первого касания и пишем строку в журнал. Дальше журнал
неизменен, баланс партнёра — сумма по журналу.

### Условия задаются у партнёра, а не в коде

Числа выше — значения по умолчанию для нового партнёра, а не константы.
Условия хранятся у каждого партнёра отдельно и правятся из раздела
рекламы: договорённости с крупным блогером и с маленьким каналом будут
разными, а менять их через выкатку новой версии бота недопустимо.

**Ставка запоминается в строке журнала начислений.** Это не мелочь: если
партнёру подняли ставку с 35% до 40%, прошлые начисления обязаны
остаться посчитанными по 35%. Иначе правка условий задним числом
переписывает уже согласованные суммы, в том числе выплаченные. Поэтому в
строке журнала лежит и сумма, и ставка, по которой она получена.

Период удержания и минимальная выплата хранятся там же. Начисление
доступно к выплате по истечении срока — чтобы возврат платежа не
превращался в долг партнёра.

### Управление из раздела рекламы

Отдельный админский раздел не заводим: партнёры живут там же, где
реклама, потому что партнёрская ссылка — это рекламная ссылка с
владельцем. Нужны экраны: список партнёров, создание, правка условий,
включение и отключение, баланс и отметка о выплате.

### Что партнёр видит и чего не видит

Метрики по своим ссылкам, воронку, баланс, историю начислений и выплат.
**Без персональных данных приглашённых** — даты и суммы, но не имена и не
телеграм-id. Это и позиция по данным пользователей, и защита от увода
базы.

- [x] Починить подсчёт выручки: подписки и транзакции присоединялись к
      пользователю одновременно, строки перемножались и сумма врала —

      спасал `DISTINCT`, сумму — ничто. Заменено на отдельные боковые
      подзапросы, проверено на живых данных.
- [x] Посадочная `/r/{код}` на сайте: считает переход, кладёт код в
      cookie на 90 дней, предлагает два пути — Telegram или регистрация
      на сайте. Неизвестный код не ошибка для посетителя: страница
      показывается без привязки. Проверено на боевых кодах.
- [x] Привязка при регистрации с сайта: код из cookie уходит боту, тот
      связывает нового пользователя с рекламной ссылкой или
      пригласившим. Раньше регистрация с сайта для рекламы была
      невидимой — переход был, а в воронке ноль.
- [x] Реферальная ссылка в кабинете ведёт на `/r/{код}`. Разосланные
      раньше `t.me/...?start=ref_` работают по-прежнему: обработчик deep
      link в боте не тронут.
- [x] Рекламные и реферальные ссылки в боте ведут на посадочную. Адрес
      сайта берётся из `BOT_SITE_URL`; пока он пуст, ссылки строятся
      по-старому, поэтому выкатка кода сама по себе ничего не меняла.
- [x] Привязка проверена контрольной регистрацией по обоим типам кода:
      рекламный лёг в `ad_link_users`, реферальный создал связь в
      `referrals`. Отрицательный псевдо-id веб-пользователя помехой не
      оказался. Тестовые записи удалены.

### Этап 2 — партнёрская механика

- [x] Роль `PARTNER` и права. Прав ровно одно — смотреть собственную
      статистику. Роль добавлена в конец перечня и в тип `user_role`.
- [x] Владелец у рекламной ссылки (`ad_links.owner_user_id`). Пусто —

- [x] Условия партнёра в базе со значениями по умолчанию: 35%, 7 дней,
      500 ₽. Заданы как `server_default` у колонок, а не в коде.
- [x] Журнал начислений. Считается один раз в момент подтверждения
      платежа, ставка запоминается в строке. Партнёр определяется по
      первому касанию — самому раннему переходу человека по партнёрской
      ссылке. Уникальность по `transaction_id` не даёт начислить дважды
      при повторном вебхуке.

      617 пользователей на месте.
- [ ] Экраны управления партнёрами в разделе рекламы

## Существующая рефералка не трогается

Проверено 15.08.2026: 75 связей рефералов (все первого уровня), 62
выданные награды, 17 пользователей с личной скидкой. Статус в боте не
хранится отдельным полем — он вычисляется на лету из
`paid_referrals_count` и `personal_discount`, оба лежат на пользователе.

Ничего из запланированного этих таблиц и полей не касается: меняется
только то, **куда ведут ссылки**, а не то, что записано.

**Отдельное обязательство: старые ссылки должны работать всегда.** Люди
уже разослали `t.me/vpnrain_bot?start=ref_XXXX` по чатам и постам, и мы
не можем их обесценить. Посадочная `/r/{код}` — это дополнительный вход,
а не замена обработчику deep link. Обработка `?start=ref_` и `?start=ad_`
в боте остаётся как есть; при переводе на новую схему это проверяется
отдельным пунктом.
